## The debate

Enterprise RAG adoption is shifting fast. Hybrid retrieval (BM25 + dense + reciprocal rank fusion + cross-encoder reranking) tripled in intent-to-adopt over a single quarter in Q1 2026. Simultaneously, a new thesis emerged: **per-session RAG is ending for agentic AI** — replaced by a compilation-stage knowledge layer that pre-compiles domain knowledge for agent tasks.

Both can be true. Here's how.

## Retrieve-then-generate fails agents

Agents don't ask one question — they chain ten. Each hop re-retrieves from scratch, re-embeds, re-ranks. Latency compounds. Context windows fill with redundant chunks. And multi-hop questions ("Where is the company Alice works at located?") break naive similarity search entirely.

## The compilation-stage alternative

Instead of retrieving per query, **pre-compile** knowledge into structures agents can traverse:

- Entity-relationship graphs (Neo4j) for multi-hop reasoning
- Dense vector indexes (Qdrant) for semantic fallback
- Rerankers on the union of both signals

The agent doesn't retrieve — it **navigates** a pre-built knowledge layer. Retrieval becomes a lookup, not a search.

## Hybrid is the bridge

My [graph-rag-multi-hop](https://github.com/arnavhazra/graph-rag-multi-hop) engine implements this bridge:

1. Ingest documents → extract entities and triples → graph + vector stores
2. Query → resolve entities → generate Cypher paths + vector search
3. Union contexts → cross-encoder rerank → LLM window

Benchmark: 2-hop graph traversal in 3.4ms. Triple extraction at ~42ms/KB. This isn't theoretical — it's a Docker Compose away from reproducible evaluation.

## When to compile vs. retrieve

| Pattern | Best for | Cost profile |
|---|---|---|
| Per-session RAG | Small, dynamic corpora | High per-query |
| Compilation-stage | Stable domain knowledge | High upfront, low per-query |
| Hybrid (graph + vector) | Multi-hop + semantic | Medium, best precision |

## The implication

If you're building agents on enterprise knowledge, stop asking "which vector DB?" and start asking "what knowledge structures do my agent tasks actually need?" The answer is usually a graph — with vectors as fallback, not foundation.
